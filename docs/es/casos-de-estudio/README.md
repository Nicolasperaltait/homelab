# Casos de Estudio Sanitizados

Estos casos transforman aprendizajes operativos privados en material publico de arquitectura.

Omiten intencionalmente IPs reales, hostnames, rutas, logs, comandos y configuraciones sensibles.

## Casos

| Caso | Que demuestra |
|---|---|
| [01 - Presion de storage y postura de recuperacion](01-presion-storage-y-recuperacion.md) | criterio de recuperacion, presion de storage, validacion |
| [02 - Monitoreo bloqueado por segmentacion](02-monitoreo-bloqueado-por-segmentacion.md) | tradeoffs de segmentacion y flujos justificados |
| [03 - Eventos de backup como evidencia SIEM](03-eventos-backup-como-evidencia-siem.md) | visibilidad de seguridad como evidencia operativa |
| [04 - Migracion de storage, observabilidad y reboot controlado](04-migracion-storage-observabilidad-y-reboot-controlado.md) | cambios sensibles con rollback temporal, retiro controlado, observabilidad y validacion post-reboot |
| [05 - Acceso de agentes de IA con minimo privilegio](05-acceso-de-agentes-de-ia-y-minimo-privilegio.md) | un unico camino con interruptor fisico, lectura privilegiada acotada, y permisos dimensionados midiendo el uso real |
| [06 - Cuando un control no mide lo que dice medir](06-cuando-un-control-no-mide-lo-que-dice-medir.md) | siete verificaciones que mentian, el patron comun, y la practica de comprobar lo que tiene que fallar |
